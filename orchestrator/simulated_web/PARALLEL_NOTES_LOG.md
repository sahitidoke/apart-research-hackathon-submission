# Mandatory notes and metadata logs (implemented, unrun)

Both build_parallel_settings and run_parallel_notebooks accept independent Boolean flags mandatory_post_answer and shared_request_log, default false. Modal parallel CLI exposes --mandatory-post-answer and --shared-request-log. Legacy defaults remain; no backend/model/quantization/GPU changes. The upcoming FarmShare wrapper and fresh run ID are a separate worker's scope.

A nonempty final answer without tools is locked. That agent then receives the existing freeform append instruction and up to two attempts of 2048 generated tokens each. Notes run on its own inference worker while its peer can research, answer or write independently. Only a verified append permits that agent's next question; there is no peer barrier. A completed abstention receives a note. Unanswered length/token/request/time-exhausted slots advance without a note: there is no locked answer, and no fallback is fabricated. No answer reserve or forced final-answer phase was added, so earlier reasoning-loop exhaustion remains possible.

QA retains 4096 tokens per agent/question. Mandatory notes add up to 4096 separately, giving 49152 maximum for two agents and three questions (24576 QA plus 24576 notes). The note stage has a 240-second wall deadline from availability and records active inference seconds; subsequent readiness is bounded by the remaining stage/job allowance. Initial backend readiness remains outside QA accounting. Blank/malformed/length-terminal note outputs consume attempts and observed tokens, with one correction opportunity. Exhausted attempts, transport error, or failed save/verification stop only the author; the peer continues. Shared-authority faults retain stop-both behavior.

The central authority calls the existing direct Unicode-safe atomic append, followed by read_notebook. It checks owned entry URL, exact body, revision, visible author and SQLite body. It preserves prior entries and never URL-encodes note content. A failed verification preserves any saved entry and the locked answer without advancing. No semantic-quality guarantee is claimed. Note artifacts retain raw responses, charges, retries and host save/verify actions; results retain the immutable answer and nested mandatory_note. Total generation accounting must sum QA generated_tokens plus mandatory_note.generated_tokens, or use charged model_response events (phase distinguishes qa/note).

Shared logs expose timestamp, operation, status, local URL and actual returned title or saved entry title. Publication exposes the new entry URL. Document/note bodies, arbitrary arguments, search query strings and URL query/fragment data are omitted; this also prevents legacy encoded-save body leakage and owned snapshot-token disclosure. Full host audit remains unexposed. There is no new editing tool.

The existing BM25 log path is reused: latest 100 events, 512-character chunks, at most one history hit among five competing results, 8000-character rendered pages and 2000 owned snapshot windows. No forced exposure or guaranteed ranking. Facts only present in document bodies cannot match the log; actual titles/URLs may match. A peer must voluntarily read the notebook entry to get its content through the log route. Ordinary notebook-page search can still match note content directly, as before. Source discovery/access restrictions are unchanged.

Host persistence actions and publication/read events carry actor host_notebook_persistence, with exact public request-event IDs in note artifacts. They do not consume voluntary QA tool-call allowance and must be excluded from voluntary publication/read metrics.

Validation: 27 mocked checks passed across test_parallel_notes_log.py and prior parallel, async and searchable-history regressions. Tests cover note/research overlap, locked answers and own-agent gating, two-attempt exhaustion, verification failure and peer continuation, no note for unanswered length slots, real metadata indexing, omission of bodies/encoded text/query text, and legacy defaults. Actual three-question preflight confirms 49152 tokens. Evidence: /tmp/9b-noteslog-regression.txt, /tmp/9b-noteslog-preflight.json, /tmp/9b-noteslog-incremental.patch. No model/cloud/remote job/build/download/install/Git action. Live behavior unverified; coordinator review required.
